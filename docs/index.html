marine-frontend 教材：從零看懂一個極簡前端

一個給 drone 容器開發者「功能做完後手動測試」用的網頁：一張地圖、每台 drone 一個點、起飛和降落兩顆按鈕。 這本教材跟著開發一起長，每個 step（每個 PR）一章，由寫那段程式的同一個人（session）撰寫， 所以章裡的輸出、數字、踩到的坑都是實際跑出來的。

這是給誰看的

  • 熟 drone、熟 Python 後端，但完全不懂前端的人。不假設你知道 npm、TypeScript、瀏覽器怎麼載入程式。
  • 會用終端機、會 git clone、看得懂簡單的 bash。

整個系統長什麼樣

這個專案只是最前面那一層。瀏覽器裡的網頁透過後端 marine-backend-py（FastAPI）去問 drone，drone 再去跟模擬器 SITL 講話：

瀏覽器 ── marine-frontend（Vite dev server :5173）   ← 本教材
            │ /api/* 由 Vite 轉給
            ▼
         marine-backend-py :8100  ──►  drone-N :7070  ──►  SITL（模擬的飛控）

計畫、選型理由、每一步的驗收標準在 repo 根目錄的 ROADMAP.md；每一步量到的數字在 docs/baseline.md。

怎麼讀

  • 照順序讀。每章都建立在前一章之上，名詞在第一次出現的那章解釋。
  • 指令都在 repo 根目錄執行，也就是 clone 下來、有 package.json 的那個資料夾。第 1 章的「第 0 步」會帶你 clone。
  • 深色底、上方標著「▶ 貼上執行」的區塊是要你跑的指令，標籤會寫在哪個目錄跑：
npm test
  • 沒有標籤的區塊是實測輸出，是作者當時真的跑出來的結果。你跑出來的時間、雜湊值、drone 狀態會不一樣，每章會說明哪些不同是正常的。
  • 圖的顏色代表「誰在執行」，全書固定：
瀏覽器 Node 上的開發工具（Vite、tsc、Vitest） 外部服務（OSM 圖磚、後端、drone） 你在終端打的指令

章節

  1. STEP 1 骨架與空地圖：一個前端專案最小的樣子

    npm、package.json、Vite dev server 與 proxy、TypeScript 型別檢查、第一個測試、直接量 drone 的腳本。打開網頁有一張置中在 SITL 起飛點的地圖。

  2. STEP 2 地圖上顯示 drone 與側欄狀態（尚未撰寫）

    每秒向後端要資料，把每台 drone 畫成一個點；離線、沒有 GPS、遙測過期時怎麼顯示。

  3. STEP 3 起飛與降落按鈕（尚未撰寫）

    從網頁送出指令、顯示 drone 的拒絕理由、追蹤任務直到結束。
