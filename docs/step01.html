第 0 步：拿到程式碼，站在 repo 根目錄

Node.js 是在瀏覽器以外執行 JavaScript 的程式，角色就像 python 直譯器。 這個專案只拿它來跑開發工具，網頁本身跑在瀏覽器裡。先確認有 Node.js 24：npm 是跟著 Node 一起裝的，不必另外裝。 如果 node -v 找不到指令或版本太舊，到 nodejs.org 照說明安裝 24 版。 Ubuntu 用 apt install nodejs 裝到的版本通常太舊。Vite 8 的最低要求是 Node 20.19 或 22.12，本章用的是 24.13.0。 另外 scripts/watch_drone.sh 需要 curl 和 jq（Ubuntu 上 sudo apt install curl jq）。

node -v
git clone https://github.com/poyilee1030/marine-frontend.git
cd marine-frontend
npm ci

node -v 應該印出 v24. 開頭的版本。npm ci 跑完會多出一個 node_modules/ 資料夾，後面會解釋它是什麼。

本章之後的指令都在 repo 根目錄執行

也就是 cd marine-frontend 之後的那個資料夾（有 package.json 的地方）。每個指令塊上方都標了在哪裡跑； 沒特別寫的就是 repo 根目錄。

為什麼需要這一步

先交代背景：開發時每台模擬的 drone 都是一個 Docker 容器，裡面跑 ArduPilot 的模擬飛控 SITL， 再加一個 HTTP API（port 7070）讓外界查狀態、下指令。這些容器由另一個 repo marlin-drone 建立。 第一台叫 drone-1，位址可以用 docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' drone-1 查到，本章的環境是 172.18.10.2。

這個專案的最終目的，是讓 drone 容器的開發者做完功能後，能在地圖上看到 drone、按按鈕讓它起飛降落， 不必開完整的地面站軟體。那之前得先有三樣東西：

  1. 一個能開起來的網頁：瀏覽器打開就有地圖。step-2 會在上面畫 drone 的點。
  2. 三道自動檢查：型別檢查（欄位名打錯就報錯）、單元測試、打包。它們在這一步只檢查「幾乎是空的」程式， 但之後每一步都靠它們把關。
  3. 一支量 drone 本身的腳本：網頁上顯示的數字是這個專案的輸出，它沒辦法證明自己是對的。 「按了起飛有沒有用」要直接問 drone。

把這些放在第一步、而且單獨一個 PR，是為了讓之後每一步的差異都只有「功能」。 step-2 出問題時，可以確定不是工具鏈的問題，因為工具鏈在這一步已經驗過了。

全景：打開 localhost:5173 時發生了什麼

接下來按這張圖的順序，一站一站看每個檔案。

package.json 與 npm ci：專案用了什麼

  • scripts（強調的那幾行）：npm run 名稱 會執行對應的指令。例如 npm run check 就是跑 tsc --noEmit。test 是特例，可以省略 run 寫成 npm test。
  • devDependencies：只在開發時用的工具（型別檢查器、dev server、測試工具、Leaflet 的型別描述）。 dependencies：網頁執行時真的會用到的套件，這裡只有 Leaflet。打包時只有它會被放進最後的 .js。
  • ^1.9.4 的 ^：允許 1.9.4 以上、但不到 2.0.0 的版本。這只是「允許範圍」； 實際裝哪一版由 package-lock.json 決定，所以每台機器 npm ci 裝到的都一樣。
  • "private": true：防止不小心把這個專案發佈到 npm 的公開套件庫。
  • "type": "module"：告訴 Node 這個專案的 .js 檔用 import／export 寫法。

npm ci 和 npm install 不一樣

平常一律用 npm ci：照 lock 檔原樣裝，不會改動任何檔案。 npm install <套件> 是「新增或升級套件」，會改寫 package.json 和 package-lock.json， 只在刻意要改套件時才用，改完兩個檔一起 commit。

index.html：網頁的外殼

瀏覽器打開 localhost:5173 拿到的第一個檔案（圖 1.1 的 ①）。它只負責排版，真正的內容由 main.ts 畫上去。

  • <style> 裡的是 CSS，也就是版面規則：選擇器 { 屬性: 值; }。body 選中整個頁面， #map 選中 id="map" 的元素（# 代表 id）。<aside> 是 HTML 裡「側欄」的標籤。
  • body 設成 display: flex，#map 設 flex: 1：地圖吃掉側欄以外的所有寬度。 前面還有一段 html, body { height: 100%; }，讓頁面填滿整個視窗高度。
  • <div id="map"> 是一個空盒子，main.ts 會用 "map" 這個 id 找到它，把地圖畫進去。
  • 最後一行 <script type="module" src="/src/main.ts">：type="module" 告訴瀏覽器這支程式用 import 寫法。瀏覽器遇到 import 時，會把後面的字串當成網址、再發一次 HTTP 請求去抓那個檔案。 還有一個問題：瀏覽器其實看不懂 .ts。 能這樣寫，是因為瀏覽器要這個檔案時（圖 1.1 的 ②），Vite 會當場把 TypeScript 轉成 JavaScript 再送出去。

親眼看 Vite 轉換 main.ts

開兩個終端，都 cd 到 repo 根目錄。第一個終端跑 dev server，讓它一直開著：

npm run dev

看到 Local: http://localhost:5173/ 之後，在第二個終端跑：

curl -s http://localhost:5173/src/main.ts | head -6

實測輸出：

const L = __vite__cjsImport0_leaflet;import __vite__cjsImport0_leaflet from "/node_modules/.vite/deps/leaflet.js?v=4512f89f";
// Leaflet 的樣式；少了它，圖磚會錯位、縮放按鈕會跑版。
import "/node_modules/leaflet/dist/leaflet.css";
// SITL 預設起飛點：marlin-drone startup_sitl.sh 的 DEFAULT_LAT / DEFAULT_LON（新北）。
const HOME_LAT = 25.0226887;
const HOME_LNG = 121.4872364;

import L from "leaflet" 被改寫成瀏覽器找得到的真實路徑（/node_modules/...）： "leaflet" 只是套件名稱，不是網址，瀏覽器沒辦法照著去抓。 名字裡的 cjs 指 CommonJS，是 Node 早期的模組格式。Leaflet 1.9 用舊格式發佈，Vite 會先轉換一次。 const L = … 寫在 import 前面沒關係：JavaScript 模組裡的 import 永遠最先執行。 ?v= 後面那串每台機器不同，是 Vite 用來讓瀏覽器快取失效的記號，不用在意。 下一節的 proxy 實驗還會用到 dev server，先讓終端 1 開著。

src/main.ts：畫出地圖

  • 第 1 行 import L from "leaflet"：從 node_modules/leaflet 載入 Leaflet。之後都用 L.xxx 呼叫它。 型別檢查器怎麼知道 L.map 有哪些參數？靠 devDependencies 裡的 @types/leaflet。它只裝型別描述檔（.d.ts）， 作用和 mypy 的 stub 套件（例如 types-requests）一樣。開頭的 @types/ 是 npm 的命名空間。
  • 第 3 行 import 一個 .css：這是 Vite 的功能，瀏覽器原生做不到。Vite 會把這份樣式插進網頁。 Leaflet 靠這份 CSS 把一格一格的圖磚拼在正確位置。
  • 第 9 行：L.map("map") 找到 id="map" 的盒子；setView([緯度, 經度], 17) 把中心放在 SITL 的起飛點。 zoom 17 大約是看得清街道和建築的比例。
  • 第 12 行：圖磚網址裡的 {z}/{x}/{y} 會被 Leaflet 換成「縮放層級／欄／列」，一張 256×256 的圖就是一格。 這些請求是瀏覽器直接發給 OSM 的（圖 1.1 的 ③）。
  • attribution：OSM 的使用政策要求畫面上標出資料來源。Leaflet 會把它畫在右下角。

常數 HOME_LAT／HOME_LNG 取自 marlin-drone 的 startup_sitl.sh，是 SITL 模擬的 drone 開機時所在的位置， 所以 step-2 畫出 drone 時，它一開始就會在畫面中央。

vite.config.ts：dev server 與 proxy

export default 表示「這個檔案對外提供的主要東西」，Vite 啟動時會讀它。整份設定只有 proxy 這一項：凡是 /api 開頭的請求，Vite 都代為轉給 http://localhost:8100（圖 1.1 的 ④）。

為什麼不讓網頁直接連 localhost:8100？瀏覽器有一條安全規則叫同源政策： 網頁是從 localhost:5173 載入的，它的 JavaScript 預設不能讀取另一個「源」的回應。 「源」由協定、主機、port 三者組成，任何一個不同就算不同源，所以 localhost:8100 也算。要放行得由後端另外設定 CORS。 用 proxy 就沒有這個問題：瀏覽器從頭到尾只跟 :5173 說話，轉給後端是 Vite 在 Node 裡做的，不受瀏覽器規則管。 附帶的好處是後端位址只寫在這一個檔案裡。

確認 proxy 真的有轉發

後端在 step-1 還不存在，但這反而能驗證 proxy。dev server 開著（上一個實驗的終端 1），在終端 2 跑：

curl -i http://localhost:5173/api/health

實測輸出（節錄第一行）：

HTTP/1.1 502 Bad Gateway

同時終端 1（dev server）會印出：

7:21:22 PM [vite] http proxy error: /api/health
Error: connect ECONNREFUSED 127.0.0.1:8100

502 加上 ECONNREFUSED 127.0.0.1:8100 代表 Vite 確實試著把請求轉到 :8100，只是那裡沒有人接。 如果 proxy 沒設定，Vite 會自己回應這個網址，而不是回 502。 如果你已經照後端 repo 把後端跑起來，這裡會看到後端的回應，那也是對的。 做完按 Ctrl+C 停掉終端 1 的 dev server。

tsconfig.json：型別檢查

每個選項旁邊的註解就是它的用途。這裡只補兩件事：

  • "strict": true 是用 TypeScript 的主要理由。 drone 的 GET /get_drone_state 回傳 45 個欄位 （curl -s http://172.18.10.2:7070/get_drone_state | jq 'keys | length' 實測）， 在 step-2 裡如果把 alt_rel 打成 alt_ref，或忘了 drone 離線時位置是 null， npm run check 會在你打開瀏覽器之前就指出來。
  • "include": ["src"] 是踩過坑才定下來的，見下面的實驗。

實驗 1：確認 tsc 抓得到錯

在 main.ts 最後加一行型別錯誤，跑檢查，再還原：

echo 'const wrong: number = "not a number";' >> src/main.ts
npm run check
git checkout src/main.ts

實測輸出（npm run check 那段）：

> marine-frontend@0.1.0 check
> tsc --noEmit

src/main.ts(16,7): error TS2322: Type 'string' is not assignable to type 'number'.

錯誤格式是 檔名(行,列)。最後的 git checkout src/main.ts 會把檔案還原成 commit 裡的樣子。 跑完 git status 應該是乾淨的。

實驗 2：重現「40 個看不懂的錯誤」

開發時一度讓 include 也包含 vite.config.ts，想說設定檔也順便檢查。重現一次：

sed -i 's/"include": \["src"\]/"include": ["src", "vite.config.ts"]/' tsconfig.json
npm run check
npm run check 2>&1 | grep -c "error TS"
git checkout tsconfig.json

第三行數有幾個錯誤，實測印出 40。npm run check 的前兩個錯誤：

node_modules/rolldown/dist/shared/define-config-C7HCoqY8.d.mts(1379,11): error TS2550: Property 'asyncDispose' does not exist on type 'SymbolConstructor'. Do you need to change your target library? Try changing the 'lib' compiler option to 'esnext' or later.
node_modules/vite/dist/node/index.d.ts(1,23): error TS2688: Cannot find type definition file for 'node'.

錯誤全在 node_modules/ 裡，不在我們的程式：39 個在 Vite 的型別檔，1 個在 rolldown （Vite 內部用的打包引擎，隨 Vite 一起安裝）。原因是 vite.config.ts 會 import Vite， 而 Vite 的型別檔第一行就要求 Node 的型別（第二個錯誤 Cannot find type definition file for 'node' 說的就是這件事）。 本專案沒有安裝 Node 的型別，於是 Vite 型別裡用到的 Buffer、node:http 全都找不到，那是另外 37 個錯誤。 vite.config.ts 本身跑在 Node 上、只有幾行，所以乾脆不檢查它，而不是為它多裝一套 Node 型別。

當時同時開了一個 skipLibCheck 選項，事後分開測才發現：它也能讓錯誤消失，但只是把套件型別檔的錯誤藏起來， 而光改 include 就夠了。所以最後只留 include，少一個選項。

測試：smoke.test.ts 與「先看它紅」

這個測試沒有測任何功能，它只證明「npm test → Vitest → 能跑 TypeScript 測試」這條管線是通的。 describe 把測試分組，it 是一個測試案例，expect(實際值).toBe(預期值) 是斷言。 () => { … } 是箭頭函式，也就是匿名函式，像 Python 的 lambda，但可以寫多行。 (a: number, b: number): number => a + b 是「收兩個數字、回傳一個數字」的函式，型別標註和 Python 的 annotation 同一個意思。 Vitest 會自動找出所有 *.test.ts 來跑。

ROADMAP.md 的「工作流程規則」第 11 條規定先寫測試、先看它失敗、再寫程式。 這一步也照做了：PR #1 的第一個 commit 只有這個測試檔，那時 npm test 失敗，因為連 package.json 都還沒有； 下一個 commit 裝好 Vitest 之後才轉綠。為什麼一定要先看它紅？一個從沒失敗過的測試，你無法確定它真的有在檢查東西。 它可能根本沒被執行，或斷言寫錯了永遠為真。

實測輸出（節錄）：

Vitest 會指出哪個斷言失敗、預期和實際各是什麼，還會標出是哪一行。step-2 開始，每個新功能都要先看到這樣的輸出，才開始寫實作。

scripts/watch_drone.sh：量 drone，不量畫面

網頁上的高度、armed 狀態是這個專案算出來、畫出來的。如果 step-2 的程式寫錯了，畫面照樣會顯示一個數字，只是是錯的。 所以驗收時要直接問 drone：這支腳本每 0.5 秒向 drone 的 GET /get_drone_state 要一次狀態，印成一行。

  • set -euo pipefail：任何指令失敗就停、用到沒設定的變數就停、管線中任一段失敗都算失敗。避免腳本出錯後還繼續跑。
  • 開頭的參數檢查：$# 是參數個數，不是 2 個就印用法並以結束碼 2 離開。 ${1%/} 是第一個參數去掉結尾的 /，所以網址寫成 …:7070/ 也沒關係。
  • 迴圈跑固定次數（秒數 × 2），所以它一定會自己結束，不需要按 Ctrl+C，也不會留在背景。
  • 強調的那行：curl -s 不印進度條，-f 讓 HTTP 錯誤碼也算失敗，--max-time 0.4 最多等 0.4 秒。 寫在 if 裡面，所以單次失敗只會印一行「連不上」，不會觸發 set -e 讓整支腳本中止。
  • jq -r：從 drone 回傳的 JSON 挑出三個欄位。flight_mode 是飛控的模式編號，例如 20 是 QLAND（降落）。

跑一次（需要 drone-1 容器在跑）

drone 容器怎麼建立，見 ROADMAP.md 的「執行前置條件」。位址換成你用 docker inspect 查到的（見「為什麼需要這一步」）：

scripts/watch_drone.sh http://172.18.10.2:7070 5
echo "exit=$?"
pgrep -x watch_drone.sh || echo 無殘留

約 5 秒後自己結束，接著印出 exit=0 和 無殘留。輸出的逐行解讀在本章的「驗證」一節。

連不上 drone 時每行印 連不上 <網址>，耗時看「怎麼連不上」：主機在、但那個 port 沒有服務，會立刻被拒絕， 實測 5.06 秒結束；位址根本不存在，每次都要等滿 0.4 秒逾時，實測 9.07 秒結束。兩者都會自己結束，結束碼都是 0。

模組分工：四條指令各自叫了誰

四條 npm 指令其實都只是呼叫某個工具，工具再去讀各自的設定檔。記住這張圖，出錯時就知道該看哪個檔案：

程式碼本身的依賴很單純：index.html 載入 src/main.ts，main.ts 載入 Leaflet 和它的 CSS。 step-2 會加入 src/api.ts（向後端要資料）和 src/view.ts（把資料換成「畫在哪、什麼顏色」的純邏輯）， 整個專案的原始檔就只有這三個。

常見錯誤

前四格是這一步開發時實際踩到的；後兩格是設計上刻意避開的，標了來源。

tsc 報出 40 個 node_modules 裡的錯誤實際踩到

症狀
錯誤全在 node_modules/ 裡（39 個在 Vite 的型別檔、1 個在 rolldown），多數是找不到 Buffer、node:http。
後果
以為自己程式寫壞了，或開一堆選項去「壓掉」錯誤。
正解
include 只放 src，不要把 vite.config.ts 拉進來（實驗 2）。

檢查殘留時，永遠「還有 1 個」實際踩到

症狀
腳本早就結束了，pgrep -f watch_drone 還是回報 1 個程序。
後果
誤以為腳本沒收乾淨，去追一個不存在的問題。
正解
-f 比對的是整條指令列，會比對到「你自己正在打的這條指令」。改用 pgrep -x watch_drone.sh，只比對程序名稱。

同一個坑的變體：grep '[v]ite'實際踩到

症狀
用 ps … | grep '[v]ite' 查 vite 殘留，還是查到東西。
後果
同上。[v]ite 這個正規表示式比對的是「vite」，但 grep 自己的指令列裡寫的是「[v]ite」，所以不會比對到 grep 本身。它只擋得住這一件事，擋不住你自己這條指令裡其他地方出現的 vite（例如指令裡寫到 vite.log 這種檔名）。
正解
一樣用程序名稱比對。最簡單的做法是：dev server 一律在前景跑，用 Ctrl+C 停。

vite 留在背景，改程式畫面卻不變實際踩到

症狀
在背景啟動的 dev server 沒收掉。之後再 npm run dev，終端印出 Port 5173 is in use, trying another one...，新的 server 跑在 :5174。
後果
瀏覽器還開著 :5173，看到的是舊的那個 server，可能還是另一個資料夾的程式。改了程式碼卻看不到效果。
正解
在前景跑 npm run dev、用 Ctrl+C 停；並留意終端印出的 Local: 網址是不是 5173。

程式裡寫 http://localhost:8100/api設計上避開

症狀
瀏覽器 Console（F12）出現含 CORS 字樣的紅字，請求被擋。
後果
後端明明有回應，網頁卻拿不到。
正解
一律寫相對路徑 /api/...，交給 proxy。（本專案沒有實際觸發過，依瀏覽器同源政策推論。）

地圖盒子沒有高度設計上避開

症狀
頁面上完全沒有地圖，也沒有錯誤訊息。
後果
<div id="map"> 的高度是 0，Leaflet 畫進去了但看不見。
正解
Leaflet 官方教學要求地圖容器一定要有高度。本專案靠 html, body { height: 100% } 加上 flex 版面做到。

小結、目前限制與下一步

這一步留下了什麼

  • 一個用 npm 管理的 TypeScript 專案：npm ci 安裝，check／test／build 三道檢查。
  • Vite dev server：送出網頁、當場把 .ts 轉成 JS、把 /api 轉給 :8100。
  • 一張置中在 SITL 起飛點的 Leaflet 地圖，圖磚來自 OSM。
  • scripts/watch_drone.sh：之後每一步的驗收都用它直接量 drone。

目前的限制，也就是下一步要做的：

  • 畫面上還看不到 drone。側欄是空的。step-2 會每秒向後端的 GET /api/drones 要資料，把每台 drone 畫成地圖上的一個點。
  • proxy 只驗證到「有轉發」。後端還不存在，所以只看到 502。step-2 需要後端的 step-2 先完成。
  • 測試還沒測任何功能。step-2 會刪掉 smoke.test.ts，換成 view.test.ts，測「離線的 drone 要不要畫」「什麼時候變灰」這些判斷，而且照規則先寫測試、先看它紅。

自我測驗

瀏覽器看不懂 TypeScript，為什麼 index.html 可以直接載入 /src/main.ts？

因為那個請求是 Vite dev server 回應的。Vite 收到 /src/main.ts 的請求時，會當場把它轉成 JavaScript 再送給瀏覽器（圖 1.1 的 ②）。 打包（npm run build）時則是事先轉好，放進 dist/assets/*.js。

後端還沒開，curl -i http://localhost:5173/api/health 回 502。為什麼這反而證明 proxy 設定是對的？

502 Bad Gateway 是「代理轉發失敗」。加上 dev server 印出的 ECONNREFUSED 127.0.0.1:8100，表示 Vite 確實試著連 :8100。 如果沒有 proxy 設定，Vite 會自己處理這個網址，而不是去連後端。

沒網路時地圖是灰的，是 Vite 出了問題嗎？

不是。圖磚是瀏覽器直接向 tile.openstreetmap.org 下載的（圖 1.1 的 ③），不經過 Vite。 可以按 F12 打開 Network 分頁，看圖磚請求是不是失敗了。

為什麼 tsconfig.json 的 include 不放 vite.config.ts？

vite.config.ts 會 import Vite，連帶載入 Vite 的型別檔，而那個型別檔要求 Node 的型別（Buffer、node:http…）。 本專案沒有安裝 Node 的型別，於是冒出 40 個與本專案無關的錯誤。 它本身跑在 Node 上、只有幾行，所以不納入檢查。

step-3 要驗收「按了起飛，drone 飛到 10 m」。為什麼要跑 watch_drone.sh，而不是看網頁上的高度？

網頁上的高度是這個專案自己算出來、畫出來的。程式有 bug 時它照樣會顯示一個數字，所以沒辦法證明自己是對的。 watch_drone.sh 直接問 drone，量的是真正的下游結果。

為什麼要先看到測試失敗，才開始寫程式？

一個從沒失敗過的測試，你無法確定它有在檢查東西。它可能根本沒被執行，或斷言寫錯了永遠為真。 先看到它因為「功能還沒寫」而失敗，寫完之後轉綠，才證明測試和實作兩邊都有作用。
